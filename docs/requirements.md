# SIM 管理平台需求文档 V1.0

日期：2026-10-24。本文记录已确认需求与首期实现边界。

## 目标与范围

以 Go 编写 Linux daemon，通过 UART0 管理多个中移 ML307R，每模组一张 SIM。提供短信接收、单条发送、查询、SQLite 保存、Bark 转发及 health API。面向个人或内部使用，优先保障收信与转发可靠性。

使用主机已有互联网连接，不负责拨号。无 Web 界面、群发、自动回复、多用户、内容路由、其他推送渠道、通话、流量管理、eSIM 配置管理、多卡切换或远程固件升级。

## 架构与硬件

采用单进程模块化架构：UART 传输、AT 会话、模组适配、应用服务、SQLite 存储、Bark 通知及 HTTP API。Driver 是用户态协议适配，非内核驱动；新型号通过适配接口扩展。SIM 身份与设备身份分离，保留短信产生时的 ICCID。

同一模组 AT 命令串行执行，持续读取异步通知；不同模组独立调度。一个模组故障不影响其他模组。短信与转发任务使用同一数据库事务，不引入外部队列。

ML307R UART0 原生为 1.8V，主机侧须匹配电平。默认 115200、8N1；硬件流控按接线配置。持续在线运行，不主动启用休眠。ML307R-DL 不支持相关短信指令，不属于支持型号。必须记录实际型号、固件版本和兼容性验证结果。

本地参考资料：`ML307R/docs/` 原始 PDF，以及 `ML307R/docs-md/` 的可检索整理版本；有歧义时以原始文档和实际固件验证为准。

## 业务需求

### 设备与 SIM

- 配置稳定设备 ID、名称、SIM 标签、可选手机号、串口参数、启用状态及 Bark 目标。
- 查询型号、固件、IMEI、ICCID、SIM 状态、运营商、网络注册、信号、存储用量和最后检查时间。
- 区分离线、串口打开失败、SIM 缺失、需要 PIN、未注册和不支持的设备状态；串口打开错误使用稳定错误码归类，不将原始系统错误暴露到 API。
- 不依赖读取本机手机号，不自动解锁 PIN/PUK。身份未确认不发送；换卡后旧任务不能在新卡上执行。

### 接收

启动、重连、异步通知和定期补扫均扫描已读及未读短信，覆盖可用的 SM、ME 存储。优先使用 PDU，支持 GSM 7-bit、扩展字符及 UCS2。分别保留 SMSC 时间和平台接收时间。

首次成功完整扫描的存量短信作为历史记录，只归档、不推送；初始化标记与接收结果同事务持久化。后续扫描中未入库的记录正常转发。

短信、原始数据及任务提交成功后，再复核 SIM 身份、存储位置与内容，最后删除模组短信。写库失败不删除；删除失败保留收据并重试。扫描去重基于当前设备、SIM、存储、槽位及原始 PDU，不能仅按发件人和正文去重。索引复用必须形成新的接收记录。

解码失败保留原始数据及错误状态，推送失败提示而非虚假正文。二进制、压缩、国家语言移位编码首期不转换为正文。

长短信能力先实机验证。能取得分片时支持持久化、乱序、重复及重启恢复；默认等待 5 分钟，未收齐则标记不完整并推送已收到内容，后续收齐更新原记录并再通知一次。无法取得完整信息时保留可读数据，能力保持未验证，不承诺恢复完整正文。合并限制在同设备、SIM、发件人、引用号、编码、总片数及合理时间窗口内，冲突分片不强行拼接。

### 发送

- 指定设备、号码及正文，异步返回任务标识。
- 按实际编码校验单条容量：GSM 7-bit 最多 160 septet、UCS2 最多 70 编码单元。超长或不支持字符明确拒绝，不截断或隐式拆分。
- 必须提供 `Idempotency-Key`，同键同参数返回原任务，同键不同参数返回 409。幂等记录与短信共同保留。
- 状态：`queued/sending/submitted/failed/unknown/expired`；默认排队 5 分钟过期。
- 已开始提交但没有确定结果时记为未知；进程中断的发送也恢复为未知。失败和未知任务均不自动重发。
- `submitted` 仅表示模组确认提交，不保证运营商最终送达。

### Bark 转发

每个模组可配置多个目标。使用 HTTPS JSON POST，支持官方及自建服务；默认密钥在请求体，兼容模式可使用带 key 的路径，正文始终在 JSON 中。可见通知仅包含统一图标、英文标题、发件人号码、一个时间戳和原始短信正文，不显示模组或 SIM 信息。

通知采用统一 Apple Messages 图标，标题为 New Message，副标题为“号码 · YYYY-MM-DD HH:mm:ss”，时间固定为 Asia/Shanghai，短信原文保持不变。不设置 Markdown、验证码大字、复制动作、提示音或可见模组分组。缺片和无法解码时仅使用简短英文状态，稳定通知 ID 复用对应分段；手动补发使用新的通知 ID。

展示 JSON 总预算为 3000 字节，同时计算 UTF-8、JSON 转义、图标及必要元信息，超出时安全分段并在标题以 `n/m` 标注；各目标及分段独立持久化、执行和重试。接口成功须同时满足 HTTP 200 和 Bark 业务码 200，仅代表服务端确认。

网络异常、408、429、5xx 重试；从 5 秒指数退避，常规退避最大 15 分钟并加入抖动，尊重合理 Retry-After。请求默认超时 10 秒；从任务创建起最多自动补偿 24 小时。明确永久错误终止重试，错误和过期状态可查询。失败或过期任务可手动创建关联补发，保留旧历史。

崩溃恢复可能重复通知，不保证恰好一次，不保证手机展示或用户已读。首期无 Bark 内容加密。

### 数据、配置与安全

SQLite 使用本地磁盘、WAL、FULL 同步及外键。单数据库单进程所有权；数据库异常不以空库覆盖。提供事务式版本迁移和停机整目录备份、恢复说明。

默认保存 90 天，每日清理；未完成转发、尚在发送或组装、仍占用模组存储的记录不因到期被直接清理。配置 YAML，密钥引用环境变量，修改后重启。目录 0700、文件 0600，日志不输出正文、完整手机号、Token 或 Bark 密钥。

默认 API 绑定回环地址，单管理员 Bearer Token。远程访问需明确开放并使用 HTTPS 反向代理。数据库正文首期明文保存，Bark 使用 HTTPS 而非端到端内容加密。

## API

完整契约见 [openapi.yaml](openapi.yaml)。接口包括设备列表/详情、短信列表/详情、发送、转发任务查询/补发及详细健康状态。列表默认 50，最大 200，稳定 ID 游标分页；短信支持设备、ICCID、方向、号码、时间及状态筛选。API 时间均为 RFC3339。

错误响应包含业务码、描述和请求标识。探针 `/health/live`、`/health/ready` 不暴露敏感信息。live 与单模组、Bark 故障无关；ready 要求数据库可写、核心工作正常、至少一个模组就绪。部分故障或转发失败/积压显示 degraded，不重启整个进程。

## 默认值与验收

| 参数 | 默认值 |
|---|---|
| 扫描 / 状态检查 | 60 秒 / 30 秒 |
| 长短信等待 / 发送排队期限 | 5 分钟 / 5 分钟 |
| Bark 请求超时 / 自动补偿 | 10 秒 / 24 小时 |
| 数据保留 | 90 天 |
| 首期规模 | 1-8 模组验证基线 |

必须验证中文、英文、扩展字符、AT/URC 交错、历史归档、重启补录、提交前后崩溃、写库失败、索引复用、换卡、目标独立重试、过期补偿、幂等冲突、未知发送不重发、长短信乱序/缺片/补全、鉴权、备份恢复及 Linux 双架构构建。

硬件验收包括实际运营商收发、存储满、重启、两实机并行及不少于 24 小时稳定性观察。不得将协议模拟或只读能力查询写成真实收发验收通过。当前证据和待验收项见 [validation.md](validation.md)。
